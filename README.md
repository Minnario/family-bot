# Family Assistant

Telegram-бот для семейного планирования. Принимает задачи обычными
фразами на русском, напоминает о них и присылает сводки.

```
«Севе теннис во вторник в 3»  →  Принял: Сева — теннис, ВТ 15:00  #1
```

## Структура

```
app/
  db.py          весь SQL проекта, больше нигде его нет
  parser.py      фраза → структура (Claude Haiku, tool use)
  handle.py      что делать с разобранной фразой
  ui.py          вёрстка сообщений и кнопки
  scheduler.py   когда и что отправлять
  bot.py         Telegram: приём сообщений и нажатий
db/
  schema.sql     6 таблиц, ENUM-типы, CHECK-ограничения
parser/
  parser_prompt.md    промпт со всеми правилами разбора
  eval_dataset.json   22 фразы с эталонным разбором
  run_eval.py         прогон, точность, стоимость
```

Слои изолированы: `bot.py` не знает про SQL, `db.py` не знает про
Telegram. Когда что-то ломается, это сужает область поиска.

## Запуск

```bash
pip3 install -r requirements.txt
createdb familybot
psql -d familybot -f db/schema.sql

python3 app/bot.py          # тестовый бот
python3 app/bot.py --prod   # рабочий
```

Настройки в `.env` в корне (в git не попадает):

```
ANTHROPIC_API_KEY=sk-ant-...
DATABASE_URL=postgresql://пользователь@localhost/familybot
TELEGRAM_TOKEN_DEV=...
TELEGRAM_TOKEN_PROD=...
TELEGRAM_CHAT_ID_DEV=-100...
TELEGRAM_CHAT_ID_PROD=-100...
```

## Проверки

```bash
python3 parser/run_eval.py --runs 3   # точность парсера
python3 app/db.py                     # слой БД + CHECK-ограничения
python3 app/parser.py "фраза"         # разбор одной фразы
python3 app/handle.py "фраза"         # разбор + запись в базу
python3 app/scheduler.py morning      # сводка вне расписания
```

## Модель времени

Пять режимов, от точного к бессрочному:

| режим | пример | напоминает |
|---|---|---|
| `exact` | «теннис в 15:00» | за 10 мин |
| `range` | «с 15 до 17» | за 10 мин до начала |
| `daypart` | «прописи утром» | один раз в начале окна |
| `allday` | «в среду цемент» | только в сводке |
| `undated` | «надо газон» | никогда |

Активные часы 06:00–23:00. Утро 07–12, день 12–17, вечер 17–21.

Часы 1–7 без уточнения читаются как дневные («в 3» → 15:00), 8–11
вызывают переспрос: обе трактовки попадают в активное окно.

## Решения, зафиксированные при проектировании

**Расписание считает код, не модель.** LLM разбирает язык на входе.
Когда слать напоминание — детерминированная работа.

**Всё время в UTC, показывается в Europe/Dublin.** Ирландия переводит
часы дважды в год.

**Ежедневные задачи не переносятся.** Не сделал — статус `skipped`,
без вопросов и без попадания в отдельные дела.

**Просроченные не переезжают сами.** Автоперенос скрыл бы факт, что
дело не сделано, и `postponed_count` перестал бы что-либо значить.

**Разметка HTML, не Markdown.** Одиночное подчёркивание или звёздочка
в тексте задачи ломает отправку в Markdown целиком.

**Бот не знает, кто пишет.** Общий чат, общая база, без прав.

## Точность парсера

Haiku 4.5, `temperature=0`: 22/22 на eval-датасете, три прогона подряд
без разброса. Около $0.57 за 300 сообщений при кешировании промпта.

Датасет пополняется реальными ошибками из `message_log`, а не
придуманными фразами. Исходные 22 кейса не удаляются — это
регрессионная база.

## Что не сделано

- закреплённый план недели
- шаблоны недели и раскатка по воскресеньям
- паузы (таблица есть, интерфейса нет)
- еженедельный разбор паттернов по истории


## Работа с сервером

Сервер: Oracle Cloud, Oracle Linux 9, пользователь `opc`.
Бот работает как systemd-служба `familybot`, автозапуск включён.

```bash
ssh opc@158.178.213.121

systemctl status familybot         # состояние службы
sudo systemctl restart familybot   # перезапуск после git pull
sudo systemctl stop familybot      # остановить
journalctl -u familybot -f         # логи в реальном времени, выход Ctrl+C
```

Юнит: `/etc/systemd/system/familybot.service`
После правки юнита — `sudo systemctl daemon-reload`, затем `restart`.

### Базы на сервере

| База | Назначение |
|---|---|
| `familybot` | боевая, с ней работает служба |
| `familybot_dev` | пустая, для экспериментов |

Переключение — правка `DATABASE_URL` в `.env` и перезапуск службы.

### Грабли

**`localhost` в `DATABASE_URL` не работает.** libpq трактует его как TCP-подключение,
а `pg_hba.conf` в Oracle Linux требует для TCP ident-аутентификацию, которой на сервере нет.
Правильно: `postgresql:///familybot` — пустой хост означает Unix-сокет и метод peer.

**SSH рвётся на долгих операциях.** В `~/.ssh/config` на Mac:

    Host 158.178.213.121
        ServerAliveInterval 60

Директивы `ServerAliveExitOnFailure` не существует — ssh откажется читать весь конфиг.

**Права на конфиги.** `.env` и `~/.ssh/config` должны быть `chmod 600`, иначе ssh игнорирует конфиг, а ключи доступны на чтение другим пользователям.
